# Админ-панель

Статическая панель находится в `pages/`. Она выпускает клиентские ключи через
`POST /admin/api-keys`, не регистрирует аккаунты и не получает upstream-токены.
Админ-ключ и пароль не записываются в browser storage; после запроса поля очищаются.
Очистка полей не гарантирует немедленного удаления строк из памяти JavaScript.

Выданный ключ не выводится открытым текстом. Скачиваемый JSON содержит только
зашифрованный конверт: AES-256-GCM, случайный 12-байтовый IV, случайная 16-байтовая
соль, PBKDF2-SHA256 (310000 итераций). Пароль — минимум 12 символов; используйте
длинный уникальный пароль и храните отдельно. Расшифровка: Base64-декодировать
`salt`, `iv`, `ciphertext`, вывести 256-битный ключ из UTF-8 пароля с указанными
параметрами PBKDF2, затем расшифровать AES-GCM (128-битный тег включён в ciphertext).
Формат проверяется тестом `tests/panel.test.mjs`; интерфейса расшифровки пока нет.
Если запрос завершился неоднозначно, проверьте список ключей через админ-API до
повтора; при сбое шифрования отзовите выпущенный ключ.

## Локальный запуск

Нужен Docker Compose v2 с поддержкой `up --wait`. Передайте `ADMIN_API_KEY` и
`GATEWAY_API_KEY` через окружение из менеджера секретов (не через аргументы команд,
историю shell или файлы репозитория). Compose отказывается запускаться без них.

```sh
docker compose -f docker-compose.admin.yml config --quiet
docker compose -f docker-compose.admin.yml up -d --build --wait
curl -o /dev/null -s -w '%{http_code}\n' http://127.0.0.1:8080/health
curl -o /dev/null -s -w '%{http_code}\n' http://127.0.0.1:8080/v1/models
```

Ожидаются 200 и 401. Откройте `http://localhost:8081`, укажите шлюз
`http://localhost:8080`, введите админ-ключ, имя клиента и пароль шифрования.
Скачайте зашифрованный файл до закрытия страницы. Оба порта опубликованы только
на loopback. Это dev-профиль: клиентские ключи хранятся в памяти и теряются при
перезапуске; `/app/data` — временный tmpfs. Для постоянного хранения используйте
production-профиль с Redis. Не используйте реальные upstream-токены для smoke-тестов.

## GitHub Pages

1. В Settings → Pages установите Source: **GitHub Actions** (нужны права администратора).
2. После merge в main workflow `Pages` публикует `pages/`.
3. Ожидаемый адрес: `https://b3b3097.github.io/ai-provider/`.
4. Origin `https://b3b3097.github.io` уже добавлен в оба конфига. Origin не включает
   путь `/ai-provider/`. CORS доверяет всему origin, включая другие Pages-проекты
   владельца; для изоляции используйте отдельный домен и замените origin в конфиге.
5. Production-шлюз должен быть доступен браузеру по HTTPS; перезапустите его после
   обновления CORS. Pages не проксирует API. Не вводите админ-ключ для чужого шлюза.

## Проверки

```sh
python -m pytest -q
python -m ruff check token_abuse_engine tests
python -m token_abuse_engine.main validate config.yaml
node --test tests/panel.test.mjs
```

Валидация выполняется с обоими ключами в окружении. Node 22 проверяет Web Crypto и
обработчик панели с имитацией DOM/fetch, а не реальный браузер. CI дополнительно
валидирует Compose, запускает контейнеры и проверяет HTTP-коды и HTML панели.
Настоящий браузерный тест выпуска/скачивания описан ниже и запускается отдельно.

### Автоматический браузерный smoke-тест

После установки Python-зависимостей, с активным virtualenv и Node 22:

```sh
npm ci --prefix tests/browser
(cd tests/browser && npx playwright install --with-deps chromium)
npm --prefix tests/browser test
```

Порты 8080 и 8081 должны быть свободны. Тест временно запускает настоящий FastAPI
с dev-конфигурацией, но без upstream-провайдеров и с хранилищем в памяти, а также
статический HTTP-сервер панели. Chromium выполняет настоящий cross-origin запрос,
выпускает ключ, скачивает зашифрованный JSON; тест расшифровывает его и проверяет
авторизацию выпущенным ключом. Проверяются очистка полей и пустые localStorage /
sessionStorage. Web security браузера не отключается. Все ключи и пароль случайны,
создаются в памяти и не выводятся в логи. После проверки процессы завершаются.
Это проверка панели и API, а не замена отдельного Docker smoke-теста.

В CI этот сценарий выполняется отдельной задачей `browser`. Для нестандартной
локальной среды можно задать `PYTHON` (путь к интерпретатору) и
`CHROMIUM_EXECUTABLE_PATH` (путь к установленному Chromium).

## Vercel: второй адрес той же панели

Корневой `vercel.json` явно задаёт статический сайт: `framework: null`, пустые
команды сборки/установки, выходной каталог `pages`. Python-шлюз, Redis и секреты
не являются частью этой публикации. Не добавляйте админ-ключи или upstream-ключи
в переменные Vercel: статической панели они не нужны.

В импортированном Vercel-проекте:

1. Оставьте **Root Directory** корнем репозитория (не `pages/`), чтобы применился
   корневой `vercel.json`. Framework Preset — **Other**. Удалите конфликтующие
   ручные переопределения команд сборки/установки.
2. Production Branch — `main`. Пока PR не слит, используйте Preview ветки
   `arena/a7f66d3e-ai-provider`; после merge запустится production deployment при
   включённой Git-интеграции.
3. При необходимости выполните **Redeploy** после обновления настроек. Убедитесь,
   что `/` отдаёт панель, а `/app.mjs` и `/crypto.mjs` — JavaScript, не HTML.
4. Для Vercel production-домена задайте `PUBLIC_ORIGIN` **на сервере шлюза** равным
   точному origin панели (с `https://`, без пути и завершающего `/`). Compose
   передаёт его в gateway. Пересоздайте gateway: `docker compose up -d gateway`.
5. Origin GitHub Pages остаётся разрешённым отдельно — обе панели могут работать
   с одним API. Для локального `config.yaml` добавляйте конкретный нужный Vercel
   origin вручную; не разрешайте `*` или все `*.vercel.app` для админ-интерфейса.
6. Динамические Preview URL отличаются от production-домена и не разрешены
   автоматически. Для проверки используйте доверенный стабильный домен либо
   добавьте конкретный preview-origin на время теста.

На обеих площадках указывайте в панели отдельный HTTPS-адрес вашего шлюза.
`localhost` не означает сервер проекта: это компьютер пользователя браузера.
Успешный статический deployment сам по себе не означает, что API или модель доступны.
